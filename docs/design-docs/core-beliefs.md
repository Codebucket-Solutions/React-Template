# Core Beliefs

- The repo should be understandable from checked-in artifacts, not tribal knowledge.
- Thin page wrappers and explicit containers make routing and feature ownership legible.
- Mock-first demos are preferable to dead placeholder routes in a reusable template.
- Validation should be executable: docs, architecture, build, and browser checks should all have commands.
- Lightweight runtime signals are more useful than hidden console noise.
